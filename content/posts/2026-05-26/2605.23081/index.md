ThriftAttention：面向长上下文 FP4 注意力的选择性混合精度方法

> 导读摘要：这篇论文要解决的是一个很现实的矛盾：长上下文推理里，FP4 注意力很快，但质量掉得明显；FP16 质量好，但代价高。作者的核心观察是，FP4 造成的误差并不是均匀分布在所有注意力块上，而是集中在少数真正重要的 query-key 交互上。于是，ThriftAttention 用一个很便宜的块级打分机制，先挑出最值得“保精度”的少量块用 FP16 计算，其余仍走 FP4，再通过在线 softmax 合并两条路径。结果是：只给约 5% 的块保留 FP16，就能平均恢复 89.1% 的 FP4→FP16 质量差距，同时保留接近 FP4 的推理效率，而且上下文越长，这种优势越明显。

## 一、问题背景：为什么统一 FP4 在长上下文里会失灵

这篇论文聚焦的是长上下文推理中的注意力瓶颈。对 LLM 来说，序列一长，注意力的二次复杂度和 KV-cache 访存都会迅速成为主要开销。硬件上，Blackwell 提供了原生 FP4 能力，因此把注意力整体降到 FP4，看起来是非常自然的加速方向。

但作者指出，**统一 FP4 注意力在长上下文下会出现系统性的质量退化**。而且这不是一个小幅、平滑的退化，而是会随着上下文增长变得更严重。论文的关键切入点在于：问题并不在于“所有注意力分数都不够准”，而在于**少数特别重要的注意力交互一旦被低精度破坏，就会明显影响最终输出**。

这一点可以从下图直观看到。作者把“速度-质量”折中画成前沿曲线，ThriftAttention 明显把工作点推向了右上角：既更快，也更接近 FP16 的质量。

![​[Fig1]](figures/Fig1.png)

图里最重要的信息不是某一个具体点，而是整体趋势：只要给很小一部分块分配 FP16 预算，质量就能大幅回升，而速度仍然接近纯 FP4。换句话说，**高精度不是要“普遍提供”，而是要“精准投放”**。

## 二、核心观察：量化误差集中在少数关键块上

论文最有价值的部分，不只是提出了方法，而是先解释了为什么这种方法可能成立。

作者从注意力输出对分数扰动的敏感性出发分析：如果某个 key 的 softmax 权重本来就很大，那么它的量化误差会被 softmax 进一步放大，对输出造成更显著影响；反之，那些本来权重很小的交互，即便有量化误差，对最终结果的影响也有限。

因此，FP4 误差对输出的影响满足一个非常不均匀的结构：它与三个因素相关——量化误差大小、注意力权重大小，以及 value 与输出之间的偏差。其中最关键的是注意力权重项，它让高分注意力位置变得格外敏感。

这个结论在可视化中也很清楚。下图展示了 FP16 与 FP4 注意力权重差异在不同层、不同头、不同 query/key 块上的分布：

![​[Fig3]](figures/Fig3.png)

这张图传达的核心是：**误差不是平均撒开的，而是集中在少数块上**。这些高误差区域往往出现在近对角区域，或者少数强关注位置上，也就是那些真正决定输出的连接。正因为误差集中，作者才有空间去做“局部修复”——只把这些关键块提升到 FP16，而不必把全部注意力都切回高精度。

这也是 ThriftAttention 与稀疏注意力方法的根本区别。稀疏方法通常是“删掉不重要的块”；ThriftAttention 则是“保留所有块，但只给重要块更高精度”。前者会引入不可恢复的信息丢失，后者只是让非关键部分承受可控的量化噪声，因此往往更稳。

## 三、方法主线：两阶段选择性混合精度

ThriftAttention 的方法结构很简洁，可以概括为两步：

1. **快速筛选重要块**
2. **重要块用 FP16，其余块用 FP4，并在线合并结果**

整体流程如下图所示：

![​[Fig2]](figures/Fig2.png)

这张图对应论文的方法主线：先分块、再打分、再路由到两条不同精度路径、最后统一合并输出。它不是训练式方法，也不需要改模型参数，而是一个**训练无关的推理时机制**。

### 1. 块级重要性打分

作者把 Q、K、V 都切成块。对于每个 query block 和 key block 的配对，不直接计算完整注意力，而是先做一个很便宜的近似评分：

- 先求 query block 内 token 表示的均值
- 再求 key block 内 token 表示的均值
- 用两者点积作为该块对的重要性分数

这个思路很直接：如果两个块在均值层面已经高度对齐，那么它们大概率会产生更强的真实注意力交互。

对应的示意可以看这里：

![​[Fig4]](figures/Fig4.png)

它说明作者不是逐 token 预判，而是用块均值构造一个粗粒度代理。这个代理非常便宜，却足以支持后面的精度分配。之后，对每个 query block，只保留 top-k 个得分最高的 key block 进入 FP16 路径，其余继续走 FP4。

### 2. 两条精度路径并行计算

进入正式注意力计算后：

- 被选中的 top-k 块对，用 FP16 精确计算分数和输出；
- 其余块对，仍然使用 FP4 量化路径计算。

这里的关键不是分别算完再拼接，而是借助 **在线 softmax** 在统一归一化框架下进行累计。这样做避免了两条路径分别归一化带来的偏差，也保证最终输出仍对应一个完整注意力分布。

从算法设计上看，这一步很关键，因为它保证了 ThriftAttention 不是“局部替换”，而是**在一个一致的 softmax 累积过程中进行混合精度融合**。因此它既能保留 FP16 关键块的精度收益，也能保留 FP4 主路径的大部分效率优势。

## 四、实现细节：为什么它在硬件上真能跑得快

这篇论文不只是方法上成立，工程上也做得很扎实。作者实现了一个融合式 mixed-precision kernel，而不是把 FP16 和 FP4 拆成两个松散阶段。

实现上的要点包括：

- 使用单一 kernel 统一管理混合精度注意力；
- 先处理大量未选中的 FP4 块，保持主路径吞吐；
- 只在选中块阶段引入小范围 FP16 helper 过程；
- 通过共享内存复用 K/V tile，并对 FP4 路径做双缓冲隐藏访存延迟；
- 对不包含 top-k 块的 warp/CTA，直接绕过 FP16 路径，减少不必要的寄存器和带宽开销。

这类优化意味着，ThriftAttention 的收益不只是“理论上少算了一点 FP16”，而是确实把“绝大多数块都走便宜路径、少数块走贵路径”落实到了 kernel 调度和内存流量层面。

相关的 kernel 与端到端加速结果，论文也做了专门展示：

![​[Fig5]](figures/Fig5.png)

这张图很重要，因为它说明优势并不只停留在困惑度或 NLL 上，而是能转化为真实推理吞吐和延迟收益。尤其在更长上下文下，解码阶段的好处更明显，因为此时 KV-cache 访问成为主要瓶颈，而 FP4 恰好能显著降低这部分成本。

## 五、实验结果：恢复了多少质量，又省了多少算力

论文的实验结论可以概括为一句话：**很小的 FP16 预算，就能找回大部分 FP16 质量**。

作者在多个长上下文基准和多个模型家族上测试，包括 LongBench-v1、HELMET、RULER、PG-19，以及 Llama、Qwen、Ministral 等模型。最核心的结论是：

- 当只有 **5%** 的 query-key 块使用 FP16 时，平均可恢复 **89.1%** 的 FP4→FP16 质量差距；
- 预算增加到 **10%** 和 **25%** 时，恢复率进一步达到 **91.8%** 和 **92.4%**；
- 在长上下文端到端生成中，相对全 FP16 注意力，速度提升最高接近 **2×**；
- 并且上下文越长，ThriftAttention 相对统一 FP4 的优势越明显。

在整体长上下文效果上，下面这张表最能说明“少量高精度块就够了”：

它展示了不同 top-k 预算下的长上下文任务表现。读法很简单：把 FP16 看作质量上限、FP4 看作效率上限附近但质量受损的下界，然后看少量 FP16 配额能补回多少差距。结果很稳定：**恢复收益与预算增加呈现明显但边际递减的关系**，说明最关键的那一小部分块确实占据了主要误差来源。

进一步地，作者还按上下文长度细分评估，结论是：上下文越长，统一 FP4 掉得越厉害，而 ThriftAttention 的恢复效果越突出。

## 七、这篇论文真正的启发

这篇论文最值得记住的，不只是一个新名字，而是一个更普遍的设计思路：

- 长上下文注意力中的低比特误差是**结构化的**，不是平均的；
- 因而精度资源也不该平均分配，而应**按重要性分配**；
- 比起“删掉块”，很多时候“保留块但降低精度”更稳；
- 当硬件已经支持超低比特算子时，真正的问题变成：**哪些位置值得保高精度**。

从这个角度看，ThriftAttention 像是把“稀疏性思维”替换成了“精度分配思维”。它不问“哪些块该不存在”，而问“哪些块值得更贵地计算”。这一步视角转换很关键，也很可能对后续长上下文推理优化产生持续影响。

如果只记一个结论，那就是：**在 FP4 长上下文注意力里，少量精确修补比大规模稀疏丢弃更有效。**
