SkillOpt：用于自演化智能体技能的执行策略优化框架

> 导读摘要：这篇论文把“技能”从一次性写好的提示词，提升为一种可训练、可验证、可迁移的外部文本状态；核心做法是用独立优化器基于执行轨迹提出受限编辑，并用验证门控、拒绝缓冲与跨 epoch 慢更新，把技能优化变成接近深度学习训练范式的稳定过程。

## 一、这篇论文到底在解决什么问题

这篇工作的出发点很直接：今天很多智能体技能，仍然主要靠人工写、一次生成，或者让模型松散地“自我改写”。这些办法能偶尔带来提升，但很难像训练神经网络那样，形成**可控、可复现、可稳定迭代**的优化过程。

作者的判断是，问题不在于目标模型本身一定要改权重，而在于**智能体的过程性知识**——也就是技能文档、操作规则、工具使用习惯、输出约束、失败规避策略——本身就应该被当成训练对象。于是，SkillOpt 的核心重构是：

- **冻结目标模型**
- 把**技能文档**当作外部状态
- 用一个单独的优化器模型，基于执行轨迹对技能做小步编辑
- 只有在留出验证集上**严格变好**时，才接受更新

这使得“技能优化”第一次被写成一种很像训练过程的形式：有学习率、有验证门、有负反馈缓存、还有跨轮次的慢速元更新。

![\[Fig1\]](figures/Fig1.png)

从方法总览可以直观看到，SkillOpt 不是让模型随意重写整份技能，而是围绕“**小步修改—验证筛选—持续积累**”展开。它试图模仿参数优化的纪律，但优化对象从权重换成了文本技能。

## 二、SkillOpt 的方法主线：把技能当作“外部可训练状态”

论文最重要的概念，是把技能视为冻结智能体之外的一层可训练状态。技能不是临时提示，而是一个可持久保存、可导出、可迁移的文本工件，部署时通常就是一份紧凑的 `best_skill.md`。

形式上，给定目标模型、任务和执行环境，当前技能会被插入智能体上下文中；模型执行任务后，环境返回：

- 执行轨迹
- 成功/失败证据
- 一个标量分数

接下来，SkillOpt 不直接根据单条轨迹大改技能，而是把轨迹聚合成更稳健的证据，再让优化器提出**结构化编辑**。这些编辑只有三类：

- 增加
- 删除
- 替换

这种设计非常关键。它避免了“整篇重写”带来的语义跳变，让技能优化更像局部梯度步，而不是一次随机漂移。论文将其类比为一种**文本空间中的受控优化**。

![\[Fig2\]](figures/Fig2.png)

这张流程图把整条训练链路拆得很清楚：先 rollout 收集证据，再按成功/失败进行反思，生成局部编辑，合并排序后形成候选技能，最后通过验证门决定是否接受。下方的跨 epoch 总结模块，则负责提炼长期有效的编辑方向。

## 三、SkillOpt 为什么能稳定：三层关键控制机制

论文的真正方法贡献，不只是“让模型改技能”，而是提出了一套能防止越改越坏的控制结构。可以概括为三层。

### 1. 文本学习率：限制每次更新幅度

作者提出“文本学习率”或“编辑预算”的思想：每轮只允许有限数量、有限规模的局部编辑。其作用和数值优化里的学习率很像——不是问“改不改”，而是问“**一次最多改多少**”。

这点很重要，因为无约束重写往往会出现两类问题：

- 为了修复一类错误，破坏原本有效的规则
- 技能文档语义漂移过快，导致后续优化历史失去连续性

从超参数分析可以看到，SkillOpt 并不是越激进越好，中等强度、受控步长通常更稳。

![\[Table2\]](figures/Table2.png)

这张超参数分析表说明，训练数据规模、学习率形式等都会显著影响结果，但最佳点通常不在最极端配置上，支持了“受控更新优于激进改写”的设计判断。

### 2. 验证门控：只有真正泛化才接受

SkillOpt 把数据划分为训练、选择、测试三部分。其中选择集扮演了验证集的角色。候选技能必须在这部分数据上**严格优于当前版本**，才会被接受。

这相当于给技能训练加上了一个硬门：

- 训练轨迹提供优化信号
- 选择集决定是否保留修改
- 测试集只用于最终报告

这样做直接抑制了“只记住训练轨迹里的偶然补丁”。论文中特别强调，训练得分高不代表技能真的更好；真正关键的是，验证集挑出的版本能否稳定映射到测试提升。

![\[Fig3\]](figures/Fig3.png)

从训练过程曲线可以看到，不同任务上训练分数、验证最优检查点和最终测试表现并不总是同步上升。也正因为如此，验证门控不是装饰，而是整个系统避免过拟合的关键。

### 3. 拒绝编辑缓冲 + 慢速元更新：把失败也变成信号

这是 SkillOpt 最有意思的地方之一。

- **被拒绝的编辑不会被丢掉**
- 它们会进入 rejected-edit buffer，作为负反馈供后续优化参考

也就是说，系统不只学习“什么改动有用”，也学习“什么改动看起来合理但会伤害泛化”。

同时，论文还加入了 **epoch-wise slow/meta update**。它不是每一步都直接改技能，而是在更长时间尺度上总结哪些编辑方向持续有效、哪些失败模式反复出现。这像是给文本优化加了一个“动量项”或“元记忆层”。

相关消融结果很能说明问题：去掉学习率形式、拒绝缓冲或慢速更新，整体性能和稳定性都会下降。

![\[Table3\]](figures/Table3.png)

这说明 SkillOpt 的提升不是单靠更强模型“会写提示词”，而是来自一整套训练式约束共同发挥作用。

## 四、训练细节里最值得注意的设计

如果把 SkillOpt 看成一个文本优化器，它最像深度学习训练的地方，不在口号，而在训练粒度设计。

### 1. rollout batch 与 reflection minibatch 分离

系统先用当前技能执行一批任务，收集轨迹；然后在更小的 minibatch 上做成功/失败反思。作者强调，小样本反思容易得出轶事性补丁，而适度 minibatch 更容易暴露可复用的过程错误，比如：

- 总是搜索错信息源
- 总是忘记验证工具输出
- 总是答对内容却用错格式

这也是为什么论文单独分析了 minibatch 大小的影响。

![\[Table8\]](figures/Table8.png)

从这组结果看，过小的 batch 噪声太大，过大的 batch 又可能让更新过于迟钝；中等规模通常更适合提炼稳定的过程规则。

### 2. 成功与失败要分开看

SkillOpt 在反思阶段并不是简单汇总所有轨迹，而是刻意区分：

- 失败案例：提出缺失规则、纠错规则
- 成功案例：保留已有效的行为模式

这使技能更新不只是“补漏洞”，也是“别把好东西删掉”。从方法上看，这比单纯围绕错误修补更完整，因为过程技能本身就包含正负两类知识：该做什么，以及不要破坏什么。

### 3. 优化器可以比目标模型更强，而且部署零额外调用

论文还专门分析了优化器强度的影响。结论是：更强的优化器通常能训练出更好的技能。

![\[Table5\]](figures/Table5.png)

这点的现实意义很大：离线训练阶段可以使用更强、更贵的优化器模型，但部署阶段只保留最终技能文档，不增加任何额外推理调用。因此，训练成本和部署成本被有效解耦。

### 4. 学到的技能保持紧凑，而不是无限膨胀

作者报告，最终导出的技能通常只有约 300 到 2000 token，而且常常只经过 1 到 4 次被接受的编辑就能形成有效版本。

![\[Table6\]](figures/Table6.png)

这很关键。它说明 SkillOpt 并不是靠把提示词越堆越长来换性能，而是在有限编辑下形成紧凑、可审计、可部署的过程规则。

## 五、实验结果说明了什么

论文在 6 个基准、7 个目标模型、3 类执行环境上做了总共 52 个评测单元，覆盖 direct chat、Codex 风格 agent loop 与 Claude Code 风格环境。主结果非常强：

- SkillOpt 在 **52/52** 个单元上达到最优或并列最优
- 相比无技能基线，GPT-5.5 平均提升：
  - direct chat：**+23.5**
  - Codex 风格环境：**+24.8**
  - Claude Code 风格环境：**+19.1**

![\[Table1\]](figures/Table1.png)

更重要的是，它不是只赢一种基线，而是系统性超过：

- 人工技能
- 一次生成的 LLM 技能
- TextGrad
- GEPA
- Trace2Skill
- EvoSkill

这说明 SkillOpt 的优势不只是“会写技能”，而是把技能训练成了一个真正受控的优化问题。

## 六、比主结果更重要的结论：技能可以迁移

如果只在原任务上变好，这篇论文仍然只是一个强技巧；真正让它有长期价值的，是**迁移性**。

作者考察了三种迁移：

- 跨模型
- 跨执行环境
- 跨相邻基准任务

结果显示，优化后的技能通常仍能带来正向增益。

![\[Table4\]](figures/Table4.png)

这意味着 SkillOpt 学到的不是某个训练配置下的死记硬背，而是更抽象的过程规则。比如如何组织搜索、何时校验工具结果、如何约束输出格式，这些策略本来就具有一定可移植性。

从应用角度看，这非常重要：技能可以先在一个更强模型或更成熟环境中优化，再迁移到邻近模型、不同 harness，甚至相关任务上使用，从而降低适配成本。

## 七、如何理解这篇论文的贡献边界

这篇论文最值得记住的，不是某个具体 benchmark 数字，而是它提出了一个清晰的方法论：

1. **技能是外部状态，不只是提示词**
2. **外部状态可以被训练**
3. **训练文本技能需要像训练模型一样有步长、验证和长期记忆**
4. **一旦训练好，技能可以作为紧凑工件被复用和迁移**

它的贡献不是再造一个技能库，而是第一次把技能优化写成近似深度学习优化器风格的流程。尤其是：

- 有界编辑替代无约束重写
- 验证门控替代主观自我感觉“好像更好”
- 拒绝缓冲把失败编辑转成负信号
- 跨 epoch 慢更新保留长期稳定方向

这些设计共同回答了一个核心问题：**如果技能本身就是适配层，应该怎样训练它？**

## 八、最后的三点 takeaway

- **方法层面**：SkillOpt 把技能训练从“提示改写技巧”提升为“受控文本优化过程”，这是论文最核心的思想跃迁。  
- **工程层面**：它不改目标模型权重，部署时也不增加额外模型调用，因而特别适合闭源前沿模型和高成本环境。  
- **应用层面**：训练好的技能是紧凑、可审计、可迁移的文本工件，这让它比一次性 prompt 优化更接近真正可复用的软件资产。
